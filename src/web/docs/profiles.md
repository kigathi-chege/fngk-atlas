# Profiles and connection scope

## Purpose
A FNGK profile identifies the local operator and Device connection context used by Atlas.

## Before you begin
Make sure the intended profile is logged in, paired where needed, and has a running compatible daemon.

## Normal workflow
Atlas selects the current profile on startup. Switch profiles only after saving or discarding edited files. Existing remote terminal sessions are not terminated when Atlas reloads, but their local panel views detach.

## What you will see
Connection status names the active profile and whether authentication or availability is missing.

## Recovery
Use Device lifecycle to see the profile's exact readiness and repair option.

See also: [Recovery](atlas-doc:recovery), [Files](atlas-doc:files), and [Terminals](atlas-doc:terminals).
